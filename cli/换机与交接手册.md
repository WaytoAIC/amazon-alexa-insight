# 换机 / 交接手册

把 apinsight 采集器部署到一台新机器，或交给另一个人使用。全程约 30 分钟，其中人工只占 5 分钟。

> 详细命令与参数见 [README.md](README.md)，本文只讲最短路径。

---

## 一、准备依赖

### 必须的四样

| 依赖 | 要求 | 检查命令 |
|---|---|---|
| **Node.js** | ≥ 20 | `node -v` |
| **Google Chrome** | 系统安装的真 Chrome | `ls /Applications/Google\ Chrome.app` |
| **整个仓库** | 不能只拷 `cli/` 目录 | 见下方说明 |
| **一个 Amazon 美国买家号** | 能正常登录、能收 2FA 验证码 | — |

**为什么不能只拷 `cli/`**：CLI 复用了插件的三个文件，路径是写死的相对路径：

```
content/network-hook.js      网络拦截脚本（注入浏览器）
data/preset-questions.js     题库 16 分类 102 题
utils/asin-parser.js         ASIN 解析与站点域名表
```

### 装 Node（如果没有）

macOS 上不想动系统、也不想装 Homebrew，用官方 tarball 最省事，**不需要密码**：

```bash
curl -sS -o /tmp/nodeindex.json https://nodejs.org/dist/index.json && V=$(python3 -c 'import json;print(next(r["version"] for r in json.load(open("/tmp/nodeindex.json")) if r["lts"]))') && curl -sS -o /tmp/node.tar.xz "https://nodejs.org/dist/$V/node-$V-darwin-arm64.tar.xz" && mkdir -p ~/.local && tar -xJf /tmp/node.tar.xz -C ~/.local && rm -rf ~/.local/node && mv ~/.local/node-$V-darwin-arm64 ~/.local/node && echo 'export PATH="$HOME/.local/node/bin:$PATH"' >> ~/.zshrc && ~/.local/node/bin/node -v
```

装完开一个新终端，或 `source ~/.zshrc`。

### 拉代码并安装

```bash
git clone https://github.com/WaytoAIC/amazon-alexa-insight.git ~/apinsight-repo && cd ~/apinsight-repo/cli && npm install
```

`npm install` 会顺带下载 Playwright 自带的 Chromium（几百 MB）。**我们默认用系统 Chrome，这份下载用不上**，想省时间和磁盘可以跳过：

```bash
PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 npm install
```

跳过后就没有 chromium 兜底了——机器上必须有真 Chrome，这本来也是推荐配置。

### 机器本身的要求

- **要有图形界面并处于登录状态**。人工登录那步会弹出浏览器窗口，无头服务器做不了。远程机器用屏幕共享 / VNC 连过去操作。
- macOS 定时任务必须用 **LaunchAgent**（跑在用户图形会话里），不能用 LaunchDaemon。模板见 README。

## 二、测试步骤

四层，从不需要账号到完整采集，**逐层往下，某层不过就别往下走**。

### 第 0 层 · 离线自检（不需要账号、不需要网络）

```bash
cd ~/apinsight-repo/cli && node --test test/*.test.js
```

预期**全部通过**（当前 115 个，会随功能增加）。这一层验证解析、导出、账号池、截断防护等全部纯逻辑。不过就是环境或代码有问题，别继续。

### 第 1 层 · 环境自检（需要 Chrome，不需要账号）

```bash
node bin/apinsight.js doctor
```

此时还没配账号，预期输出：Node 版本 OK、playwright 已安装、浏览器通道 chrome，然后提示"账号池未配置"。**只要前三项是好的就算过。**

### 第 2 层 · 登录（唯一需要人工的一步）

```bash
node bin/apinsight.js accounts add --id us-a
```

```bash
node bin/apinsight.js login --account us-a
```

会弹出 Chrome 窗口停在 Amazon 登录页。**在窗口里自己输账号密码和验证码**——工具不读取、不输入这些内容，也不要把密码写进任何配置文件。

登录成功后命令会自动检测并退出。判定标准不是"账号栏出现名字"，而是 **Alexa 面板真正可用**。

> **这一步无法跳过，也无法用 cookie 代替。** Amazon 把登录态分两级：重放 cookie 只能到「已识别」（能浏览、账号栏显示姓名），Alexa 要求「已认证」——必须在**这台机器上**真实登录一次。面板会明说 `Please sign in to begin using Alexa`。
>
> 好消息是这是一次性的，登录态存在持久化 profile 里，之后可长期无人值守。

多个账号就重复这两条命令，换个 id（`us-b`、`us-c`……）。

### 第 3 层 · 账号自检

```bash
node bin/apinsight.js doctor
```

每个账号必须同时出现这两行才算过：

```
✓     已登录：Hello, XXX
✓     Alexa 面板可用
```

**只有第一行、第二行报错**，说明还停在「已识别」级，回第 2 层重新登录。

### 第 4 层 · 冒烟采集

```bash
node bin/apinsight.js collect --asins B0DCH8VDXF --questions summary_all --limit 2 --headless
```

预期 2 题成功、**来源都是 `network`**：

```
✓     network · 1334 字 · 10s
→ 结束：成功 2 / 错误 0 / ASIN 级失败 0 / 作废 0
```

判断要点：

| 现象 | 含义 |
|---|---|
| `network` | 正常，走的是主路 |
| 偶尔 `dom` | 主路失败回落，可接受但要留意频率 |
| 大量 `dom` 或耗时 60s+ | 不正常，查 `run.log` |
| `成功 0 / 错误 N` | 回第 3 层确认 Alexa 可用 |

结果在 `runs/<runId>/`：CSV、JSON、`results.jsonl` 明细、`run.log`。打开 CSV 看一眼 Answer 列是不是完整通顺的段落——**如果出现同一句话长短两版并存的碎片，说明代码版本旧了**，拉最新的。

## 三、日常使用

```bash
node bin/apinsight.js collect --asins B0XXX,B0YYY --questions summary_all --max-hours 10
```

ASIN 多的话写进文件，一行一个，`--asins ~/asins.txt`。

三条常用命令：

```bash
node bin/apinsight.js status        # 看进度和账号池
node bin/apinsight.js collect --resume    # 断了从上次继续
node bin/apinsight.js doctor        # 出问题先跑这个
```

### 退出码（定时任务按这个告警）

| 码 | 含义 | 处理 |
|---|---|---|
| 0 | 全部完成 | — |
| 2 | 完成但有错误行 | 看 CSV 的 Status 列 |
| 3 | 撞人机验证 | 人工处理后 `accounts enable <id>` |
| 4 | 登录态失效 | 重跑 `login --account <id>` |
| 5 | 配额耗尽 | 正常，等次日或加账号 |
| 1 | 致命错误 | 看 `run.log` |

## 四、交接给别人时要交代的三件事

1. **每台机器、每个账号都要单独登录一次**。换机器不能拷 profile 蒙混过关，Alexa 会识破。

2. **限速默认值别乱调**。当前配置每天 1200 题（约 50 个 ASIN 跑满 24 题），跑满约 9 小时——通常已经够用。调快省不下什么，但可能把买家号搞进人机验证甚至账号关联。真要调，先连续 7 天零 captcha，再一次只动一个参数。

3. **凭据不进仓库**。cookie 导出、密码、2FA 恢复码一律放仓库外（建议 `~/.config/ai-hub/`，权限 600）。`accounts import` 会主动拒绝读取 git 工作区内的文件。

## 五、卡住时先看这里

| 症状 | 原因 | 处理 |
|---|---|---|
| `找不到 Alexa 入口` | 没认证，或 Amazon 又改版了 | 先跑 `doctor`；确认已认证仍报错就是改版了 |
| `Alexa 要求完整认证` | 停在「已识别」级 | `login --account <id>` |
| 答案是重复碎片 | 代码版本旧 | 拉最新代码 |
| 答案是 "How can I help?" 之类 | 抓到面板样板 | 新版会拦截并报错，说明版本旧 |
| 大量 60s 超时 | 流被截断（旧版 300KB 上限） | 拉最新代码 |
| `npm install` 卡在下载浏览器 | 在拉 Chromium | 用 `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1` |
| 登录窗口看不见 | 机器无图形会话 | 屏幕共享连过去，或换有 GUI 的机器 |
