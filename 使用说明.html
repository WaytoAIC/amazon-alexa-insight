这是什么，能帮你做什么

做亚马逊选品和运营，最值钱的情报藏在竞品的真实评价里——差评在抱怨什么、好评在夸什么、客户最想要却没被满足的需求是什么。以前这些要一条条翻评论，现在亚马逊的 AI 导购 Alexa for Shopping（2026 年由 Rufus 改名合并而来）已经替你读完了所有评论，你只要会问。

这个插件做的事，就是替你批量地问：你给它一批竞品 ASIN，选好想了解的角度，它会自动逐个打开商品页、唤起 Alexa、把问题一条条发过去、等回答生成完，再把所有问答整理成一张表交给你。

一句话：把"挨个翻竞品评论 + 手动问 AI"这件重复劳动，变成一次设置、自动跑完、导出表格。
1

安装插件

这是一个未上架的「开发者模式」扩展，按下面 5 步加载即可，全程 1 分钟。

  1. 打开 Chrome 扩展管理页
    在地址栏输入 chrome://extensions/ 回车。（Edge 浏览器用 edge://extensions/，同样支持）
  2. 开启「开发者模式」
    页面右上角的开关，打开它。
  3. 点击「加载已解压的扩展程序」
    左上角出现的按钮（英文为 Load unpacked）。
  4. 选择本插件文件夹
    选中包含 manifest.json 的这个 alexa-insight 目录。
  5. 固定到工具栏
    点浏览器右上角拼图图标，把「Alexa 产品洞察」钉住，方便随时点开。
点击插件图标后，面板会从浏览器右侧边栏滑出（Side Panel 形式），可以和亚马逊页面并排显示，边采集边看进度。
2

三步上手

第一次用，照着这三步走，两分钟就能跑出第一批结果。

STEP 1 · 设置

填竞品、选角度

选目标站点（如 🇺🇸 US），把竞品 ASIN 或商品链接粘进输入框，再勾选想了解的「问题分类」。

STEP 2 · 采集

点「开始采集」

插件自动打开商品页、唤起 Alexa、逐条提问。切到「进度」页看实时日志，期间你可以去做别的事。

STEP 3 · 导出

导出表格分析

跑完自动跳到「结果」页。按 ASIN / 分类筛选，一键导出 CSV、Excel 或 JSON，拿去做对比分析。

3

核心流程：三个标签页

面板顶部有三个标签——设置 → 进度 → 结果，正好对应一次采集的全过程。

✏️ 设置

配置这一次要采集什么。

  • 目标站点：US / UK / DE / JP 等，决定打开哪个亚马逊。
  • 竞品 ASIN：支持逗号、换行、商品链接混合粘贴，自动识别去重并显示数量。
  • 问题分类：勾选要问的角度，下方可展开预览具体问题。
  • 自定义问题：每行一个，补充你自己的问法。
  • 保存配置：记住这套设置，下次打开自动带出。
📈 进度

实时盯着采集跑到哪了。

  • 总体进度条+ 三个计数：ASIN 完成 / 问题完成 / 已采集。
  • 当前任务：正在问哪个 ASIN 的哪个问题。
  • 活动日志：每一步的成功/重试/失败都有记录。
  • 暂停 / 停止 / 清除：随时中断，任务状态会被保存，可恢复。
📄 结果

查看、筛选、导出问答数据。

  • 结果表：ASIN / 分类 / 问题 / 回答 / 状态。
  • 筛选：按 ASIN、按问题分类快速过滤。
  • 导出：CSV、Excel、JSON 三种格式。
  • 清除：清空本地已存结果。
采集是断点续传的：中途暂停、关闭面板甚至意外退出，重新打开后任务进度还在，可以接着跑。结果实时存在浏览器本地，不会丢。

5

采集策略参数

设置页底部的「采集策略」决定插件如何判断"Alexa 答完了"。默认值已经调好，一般不用改。

参数默认作用 & 调整建议
稳定次数3回答连续 N 次检查都没有变化，就判定"生成完成"。调高更稳但更慢，调低更快但可能没等答完就进入下一题。范围 2–8。
间隔 (秒)1.5每隔多久检查一次回答还在不在变化。范围 0.5–5 秒。
超时 (秒)60单个问题最长等待时间，安全兜底——超过就跳过，避免卡死。回答普遍较长时可适当调高。范围 15–120。
插件会自动检测回答是否还在生成，确认稳定后才发下一题。这三个参数就是在"快"和"稳"之间找平衡，不确定就保持默认。
6

高级设置（齿轮按钮）

面板右上角 ⚙️ 进入。大多数人不需要碰，遇到页面改版或想要中文结果时才用。

🎯 Alexa / Rufus 选择器配置

亚马逊已把 Rufus 改名 Alexa for Shopping，但页面内部的 DOM 元素仍叫 rufus。插件靠几条 CSS 选择器找到"入口按钮 / 输入框 / 发送按钮 / 回答容器"。

如果哪天亚马逊改版导致唤不起 Alexa 或采不到回答，可以在这里覆盖默认选择器（填了就优先用你的）。点「恢复默认」可一键还原。

这是给会看网页源码的人留的"应急修复口"。不懂 CSS 选择器就别动，保持默认即可。

⚙️ 其他开关

自动滚动到 Alexa 窗口采集时把页面滚到 Alexa 对话框，便于观察。默认开。
失败自动重试单条问题失败时自动重试，最多 2 次。默认开，建议保持。
同时采集标题和价格顺带抓取商品标题与价格，写进导出表。默认开，做对比分析很有用。
7

回答处理：翻译与大模型

Alexa 的回答是英文。在高级设置的「🌐 回答处理方式」里，选择英文回答如何落到表里。

模式速度说明
不翻译最快保留英文原文。想自己读原汁原味、或后续用别的工具处理时选它。
免费翻译中等用 MyMemory / Google 免费接口译成中文，零配置，质量一般、长文可能被截断。
大模型翻译取决于模型质量最好。调用大模型翻译，需要填接口配置（见下）。导出表里会同时保留中文译文和英文原文。

配置大模型翻译

选「大模型翻译」后展开配置，支持两类接口：

  • OpenAI 兼容：本地 Ollama / LM Studio，以及 DeepSeek、OpenRouter 等。
    Base URL 形如 http://localhost:1234/v1，模型名如 qwen2.5:7b、gpt-4o-mini。本地服务 API Key 可留空。
  • Anthropic（Claude）：Base URL https://api.anthropic.com，模型如 claude-3-5-haiku-latest。

填好后点 「测试连接」确认通了，再保存。

优先推荐本地大模型（Ollama / LM Studio）：免费、不限量、隐私好，翻译这种活儿小模型完全够用，数据也不出本机。
8

导出结果

「结果」页底部三个导出按钮。CSV 与 Excel 都是带 BOM 的表格文件，Excel / 飞书 / Numbers 直接打开不乱码。

格式适合场景
CSV / Excel表格分析首选。一行一条问答，方便筛选、透视、跨竞品横向对比。
JSON给程序/脚本二次处理，含导出时间等元信息。

表格里有哪些字段

每一行是一条问答，包含以下列：

ASIN · Product Title（标题）· Price（价格）· Category（分类）·
Question（问题）· Answer（回答/译文）· Answer (EN)（英文原文）·
Status（状态）· Timestamp（时间戳）

结果会实时保存在浏览器本地，采集完成时也会自动导出一份 CSV。即使忘了手动导，数据也还在「结果」页里。
9

常见问题排查

没识别到 ASIN？

确认输入里含标准 10 位 ASIN（形如 B0XXXXXXXX），或直接粘贴完整商品链接。输入框下方会实时显示"已识别 N 个 ASIN"，以它为准。

Alexa 没打开 / 采不到回答？

最常见原因是亚马逊页面改版，插件找不到 Alexa 入口了。处理顺序：

1. 先手动在该商品页确认 Alexa for Shopping 入口确实存在、能用；
2. 部分站点 / 部分商品可能尚未开放 Alexa，换个 ASIN 或换 US 站试试；
3. 仍不行就到「高级设置 → 选择器配置」更新对应选择器，或点「恢复默认」。

采集速度慢？

瓶颈在 Alexa 实时生成回答，本身就需要等待。可适当调低「稳定次数」或「间隔」，但别太低，否则可能没等答完就跳下一题。更有效的做法是减少每轮的问题数量，用「⭐ 核心必问」代替勾一堆分类。

结果会丢吗？存在哪？

不会。结果实时存在浏览器本地存储，关掉面板、重启浏览器都还在，可在「结果」页随时导出。这也意味着数据不上传任何服务器（除非你开了大模型翻译，那部分回答文本会发给你自己配置的翻译接口）。

中途能暂停吗？会不会要重头来？

能。「进度」页的暂停 / 停止会保存当前任务状态，重新打开可恢复继续，已采集的部分不会丢，不用重头跑。

翻译出来质量不好 / 被截断？

免费翻译（MyMemory / Google）对长文本质量有限。要好结果就切「大模型翻译」，配一个本地 Ollama 或任意 OpenAI 兼容接口；不需要中文的话直接用「不翻译」保留英文原文最稳。
